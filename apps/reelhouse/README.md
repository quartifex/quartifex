# reelhouse

Docs and playground. **Open-source demo.** Planned address: `reelhouse.quartifex.com`.

Docs and a live playground for our image-sequence pipeline. Drop a video (or take our
sample), and rushes' preview encoder turns it into tiered frames in the browser tab; reel plays
them back with a scrub and a tier switch; viewfinder shows reel's buffer live; the tier table
weighs the real bytes against a budget the way rushes and heft do, then hands over the CLI
command and `budget.json` block to ship it. Nothing is uploaded. It proves we build tools, not
only pages.

Built with `@quartifex/rushes` (the build-time hero and the in-browser preview encoder),
`reel`, `heft` and `viewfinder`.

## Run

```sh
pnpm --filter @quartifex/site-reelhouse dev      # http://localhost:3300
pnpm --filter @quartifex/site-reelhouse build    # encodes the hero sequence, then builds
pnpm --filter @quartifex/site-reelhouse start
```

The build draws the 72 hero frames in code (`scripts/aperture.mjs`) and encodes them with rushes
into `public/sequences/aperture/` (git-ignored, about 3 MB on disk, under 1 MB per tier).

## Checks

```sh
pnpm --filter @quartifex/site-reelhouse e2e      # behaviour tests and the launch gate
PW_CHANNEL=chrome pnpm --filter @quartifex/site-reelhouse sheet   # contactsheet, all 36 profiles
PW_CHANNEL=chrome pnpm --filter @quartifex/site-reelhouse heft    # budget.json "reelhouse" block
```

`sheet` and `heft` start the production build themselves (build first) and write to
`reports/reelhouse/`. The JSON, HTML and Markdown reports are committed; screenshots stay local.

## Deploy

`vercel.json` installs from the repo root and builds with Turborepo. Set the Vercel project's
root directory to `apps/reelhouse` and the domain to `reelhouse.quartifex.com`. Optional:
`QX_FONT_ORIGIN` for the brand fonts (see `licence-check.md`, Fonts).

## Honest limits

- The playground uses the browser's own image encoders. Its WebP bytes land close to the CLI's
  (within a few percent on our sample) but are not identical; ship with the CLI.
- Most browsers cannot encode AVIF from a canvas yet. There the AVIF rows are an estimate, marked
  as one: the WebP bytes times the AVIF-to-WebP ratio the CLI measured on our sample.
- A browser that can encode neither (older Safari) says so and points to the CLI.
- Long clips are sampled evenly down to the frame count chosen (24 to 144).

## Provenance

- Hero: concept visual, a lens iris drawn in code (procedural SVG frames encoded by rushes). Not
  a photograph or film footage.
- Playground sample: the same sequence, re-encoded in the browser.
- Visitors' clips: read and encoded in the tab only; nothing is uploaded, stored or sent.
- Icon: from the Quartifex icon set (`assets/icons/svg/S03-reelhouse.svg`).
- No photographs, video, models, datasets or sound are shipped.

## Launch gate

Do not deploy until every line is true.

- [x] The label is on the page and accurate: Open-source demo. Nothing invented is presented as
      real.
- [x] Rendered or generated visuals are captioned "Concept visual".
- [x] No raster, video or client-owned model is committed: the sequence is generated at build.
- [x] `prefers-reduced-motion` has a complete, usable path: the hero shows its poster and loads no
      frames; the playground has no autoplay, and the scrub still works.
- [x] Keyboard: a skip link to the playground, native controls throughout, visible focus.
- [x] LCP under 2.5 s and CLS under 0.1 on a mid-range mobile profile (Playwright, Pixel 7, 4x
      CPU, Lighthouse mobile network): see `e2e/launch-gate.spec.ts`.
- [x] Page weight within the `reelhouse` budget in `budget.json`, checked by heft.
- [x] contactsheet run across the device matrix, report in `reports/reelhouse/`: no flags.
- [x] Playwright behaviour tests pass against the production build.
- [x] `pnpm check` is green. Catalog entry marked `built`. `STATUS.md` updated.
